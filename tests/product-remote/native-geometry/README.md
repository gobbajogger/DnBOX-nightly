# Native source geometry, not UI admission

The five `remote/native-geometry/` modules are deliberately unbound to the app. They port native firmware source b341436ff8087c20b8ef51765f986736473611b0, preserving single-precision arithmetic and native descriptor identity. Source hashes are recorded in `source-pins.json`.

The C references retain the native `dv_tune_fork`, DG_ATTACK and DG_DECAY/DG_NTAIL expressions from `firmware/src/app/ui_drum_voice.inc`. The copied `fastmath.h` is exact native source. The small wrappers serialize coordinates and supply explicit numeric SI inputs; they do not claim to be the full firmware, renderer or audio engine. Every reference compiles with floating-point contraction disabled, as the native source requires. Only local temporary executables are built, with timeouts and cleanup; no binary is distributed.

`numeric-decay-contexts.json` contains the 22 Decay/Noise Tail controls selected from a separately source-reviewed actual b341 `engine_param_si` fixture. It retains typed identities, raw ranges, numeric unit IDs, exact float bits, boot dependency vectors and idle context. The full export's SHA256 is recorded. The producer ran 32,589 checks, including unchanged entire selected-kit preferences. Independent review verified the exact source/context receipts and numeric bit roundtrips, but did not independently rebuild that entire native-host fixture. Unknown-unit outputs initialized to zero are not physical-unit claims. No raster buffers or screenshots are included.

Run `node --test tests/product-remote/native-source-geometry.test.mjs`. This recompiles C and compares 7,280 Tune/Attack geometry cases, 12,258 math cases and 11,264 Decay cases. Quarter-raw values are geometry-interpolation diagnostics, not permission to write fractional engine parameters. Tune/Attack typed selection requires the exact source/name/domain/identity and excludes Pitch/Depth rather than silently aliasing them. Attack is amount, not time. Decay retains source numeric-unit branches and fallback, including the distinct 808 path.

Still required before visible binding: verified current context at the caller, actual typed app wiring, native raster/stroke/color parity, easing and live-state behavior, equivalent-state layout review and all lane gates. No native transport, hardware, full Local, browser or lane PASS follows from these source tests. Existing browser glyph behavior is unchanged by this package.

The portable runner captures and hashes module, JSON context, C and header bytes once, imports/parses only those bytes, compiles staged copies and verifies them around execution. A negative replaces original C/header paths after capture and proves the staged executable still uses the captured inputs; a fresh capture rejects the replacements. This closes the earlier separate-hash/live-compile gap.
